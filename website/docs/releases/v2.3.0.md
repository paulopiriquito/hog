# HOG v2.3.0

A minor release that changes nothing in the module's API: the published
images now build with Go 1.27, so a gateway or plugin module composed by
`hog-builder` may declare `go 1.27`. The floor in `go.mod` stays at Go 1.26.

## Why the builder's Go version matters

`hog-build` composes a binary from the HOG source and the plugins a `Gateway`
lists, and it compiles that binary with the toolchain inside `hog-builder`.
The image pins the `go` command to its own installed toolchain rather than
letting it download another: a build inside a container should not reach out
for a compiler, and the binary a tag produces should be the same binary
tomorrow.

The consequence of that pin is that the builder's Go version is the ceiling
for every module it compiles. A plugin whose `go.mod` said `go 1.27` could not
be composed by `hog-builder:v2.2.0`, whose toolchain is Go 1.26, and the build
failed with the toolchain's own message rather than anything HOG could
explain. Operators were left choosing between an older `go` directive in
their plugin and a builder they had to maintain themselves.

`hog-builder:v2.3.0` carries Go 1.27. `hog-runtime` and `hog-static`, which
compile the vanilla `hog` binary, build with the same version, and so does the
backend image the end-to-end suite runs against.

## What stays

- `go.mod` still declares `go 1.26`. HOG as a framework dependency keeps
  working from a Go 1.26 module, and nothing in this release uses a Go 1.27
  language or library feature.
- The test suite now runs on Go 1.26 and on Go 1.27, so the floor and the
  ceiling are both exercised on every change.
- `hog-build` still writes `go 1.26` into the module it composes; the `go`
  command raises that line to whatever the plugins require, as it always did.

## Upgrading

Pin `hog-builder:v2.3.0` and `hog-runtime:v2.3.0` in the two-stage
Dockerfile. A plugin module may then raise its `go` directive to a Go 1.27
release the builder carries. A directive newer than the builder's toolchain is
still refused at build time, as before, because the toolchain is pinned.
