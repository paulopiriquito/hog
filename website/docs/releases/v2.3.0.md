# HOG v2.3.0

A minor release that moves HOG to Go 1.27. The module floor, the published
images and the module `hog-build` composes all move together, and the code
adopts what the 1.27 library offers. Nothing in the configuration model or the
module's API changes.

## The floor moves to Go 1.27

`go.mod` now declares `go 1.27`, and so do the nested session-store plugin and
the module `hog-build` writes when it composes a binary. A module that imports
`github.com/paulopiriquito/hog/v2` must therefore declare `go 1.27` or newer
itself; the `go` command says so at the first `go get` and raises the line
when asked.

Moving the floor and the images at the same time is deliberate. Before this
release the two could disagree: `hog-builder` pins the `go` command to its own
installed toolchain rather than letting it download another, so the builder's
Go version is the ceiling for every module it compiles, while `go.mod` set the
floor somewhere below it. A plugin whose `go.mod` said `go 1.27` could not be
composed by `hog-builder:v2.2.0`, whose toolchain is Go 1.26, and failed with
the toolchain's own message rather than anything HOG could explain. With both
on 1.27 there is one number to know.

## The images

`hog-builder:v2.3.0` carries Go 1.27. `hog-runtime` and `hog-static`, which
compile the vanilla `hog` binary, build with the same version, and so does the
backend image the end-to-end suite runs against. The test workflow installs
the toolchain `go.mod` names, so the suite runs on the version the images
ship.

## What the code adopts

The 1.27 modernizers ran across the module, and the result is what a reader
of the current language expects: range-over-integer loops, `strings.SplitSeq`
where a split was only ever iterated, `slices.Backward` for the middleware
chain's reverse walk, `slices.Contains` and `maps.Copy` in place of hand
loops, `sync.WaitGroup.Go` in the tests, `new(expr)` for pointer literals, and
the `min` builtin. The plugin entry parser uses `strings.CutLast` to split
`<import-path>@<version>`. None of these change behaviour; they remove code.

## Security

**The access log redacts credential headers at the logging site.** Loading a
configuration already refused `Authorization`, `Cookie`, `Proxy-Authorization`
and `Set-Cookie` under `accessLog.headers`. The middleware now enforces the
same rule itself, writing `REDACTED` for those headers whatever field name
they were configured under, so a configuration assembled in code rather than
loaded from YAML cannot route a bearer token into the log. `X-Hog-Identity`,
the signed assertion one instance hands to another, joins the list in both
places: within its validity it is as good as the session it describes.

**Dependencies past their advisories.** `google.golang.org/grpc` 1.83.1 and
the OpenTelemetry SDK and OTLP trace exporters 1.45.0, in the module and in
the session-store plugin.

## Upgrading

Raise the `go` directive of any module that imports HOG to `1.27`, and pin
`hog-builder:v2.3.0` and `hog-runtime:v2.3.0` in the two-stage Dockerfile. A
plugin composed by the builder may declare any Go 1.27 release the builder
carries; a directive newer than the builder's toolchain is still refused at
build time, as before, because the toolchain is pinned.
